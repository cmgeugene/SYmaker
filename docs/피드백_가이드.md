# SYmaker 피드백 처리 가이드 (에이전트용)

사용자가 **문제지에 대한 피드백**(선생님·검토자 수정사항, 출력물을 보고 느낀 점 등)을 붙여 넣으면 이 가이드대로 처리한다.
목표는 피드백 하나하나를 아래 둘 중 하나로 정확히 안내하는 것이다.

- **앱에서 할 수 있는 것** → 어느 화면에서 무엇을 누르고 무엇을 입력하는지 그대로 따라 할 수 있게 알려 준다.
- **코드를 고쳐야 하는 것** → 왜 앱으로는 안 되는지(원인)와 수정안을 제안하고, **사용자가 승인한 뒤에만** 고친다.

모든 답은 한국어로, 사용자는 개발자가 아닐 수 있으므로 쉬운 말로 쓴다.

---

## 1. 처리 순서

1. **현재 상태부터 확인한다.** 어떤 프로젝트·문제집 이야기인지 파악하고, 설정을 추측하지 말고 실제 값을 본다 (§6 조회 방법).
   - 예: 적용 중인 지침, 양식 구성(사용/택1), 출력 서식, 자료의 지문 사용 방식, 최근 출력 파일.
2. **피드백을 항목별로 나눈다.** 한 문장에 여러 요청이 섞여 있으면 쪼갠다.
3. **항목마다 분류한다** (§2 판단 기준, §3 앱 기능 지도).
4. **표로 답한다** (§5 답변 형식). 앱으로 되는 건 바로 따라 할 수 있는 순서와 붙여 넣을 문구까지 준다.
5. **코드 수정이 필요한 항목은 제안만 하고 승인을 기다린다.** 승인 후 수정 → 빌드·재시작 → 다시 출력 → 확인 (§7).
6. 사용자의 문제집·자료·지침을 직접 바꾸거나 Codex 작업(제작·수정·배치)을 돌리는 것도 **사용자가 그렇게 해 달라고 했을 때만** 한다.

## 2. 판단 기준 — 앱으로 되나, 코드를 고쳐야 하나

| 피드백의 성격 | 처리 | 이유 |
|---|---|---|
| 지금 만든 문제의 **내용**(지문, 발문, 선택지, 정답, 해설) | 앱: 피드백 → **문제에 반영** | Codex가 해당 문항/지문 세트만 다시 쓴다 |
| **앞으로 계속** 지킬 출제 원칙 (예: 어법 포인트 골고루, 오답 설계 방식) | 앱: 피드백 → **지침·자료 설정 제안** 또는 출제 지침 직접 수정 | 지침은 다음 제작부터 프롬프트에 들어간다 |
| 자료를 **쓰는 방식** (원문 그대로/패러프레이징, 패러프레이징 분량·난이도·메모, 출제 범위) | 앱: 자료실 카드 설정 | 자료 설정이 제작 프롬프트에 들어간다 |
| 문항 **구성**(어떤 하위 문항을 쓸지, 택1, 순서) — 양식 모드 | 앱: 샘플 분석 → **양식 구성** | |
| **출력 서식** 중 이미 설정이 있는 것 (§3-F) | 앱: 샘플 분석 → **출력 서식** | |
| 양식 칸의 **글꼴·크기·정렬·줄간격** 자체 | 우선 **양식 파일(HWP)을 한글에서 고쳐 다시 올리기** 안내. 일부 칸만 바꿔야 하면 출력 서식으로 되는지 확인 | 출력은 양식 문단 모양을 복제한다 |
| 출력 서식인데 **설정이 없는 것** (새 서식 종류, 새 정답 표시 방식, 칸별 줄간격 등) | **코드 수정 제안** | |
| 앱이 **잘못 동작**하는 것 (설정대로 안 나옴, 오류 메시지, 화면 깨짐) | **코드 수정 제안** (버그) | |
| 정답 표시가 **학생용에 새는 것** | **코드 수정 제안** — 최우선 | |

애매하면: "지금 앱에서는 ○○까지만 됩니다. 나머지는 코드 수정이 필요합니다"처럼 나눠서 답한다.

주의: 피드백 단계의 Codex는 **문제 내용과 지침·자료 설정만** 바꿀 수 있다. 글자 크기·정렬·빈 줄·문항 순서·정답 표시 서식 같은 **출력 방식은 피드백 문구로는 바뀌지 않는다** — 설정이나 코드로 처리한다.

## 3. 앱 기능 지도 (화면 경로)

앱 주소: http://127.0.0.1:8765 (꺼져 있으면 `./start.sh`)
문제집 화면 단계: 1 자료 등록 → 2 샘플 분석 → 3 문제 제작 → 4 검수 → 5 HWPX 출력 → 6 피드백

### A. 문제 내용 고치기
- **피드백 반영**: 6 피드백 → 대상(문제지 전체 / 특정 문항) 고르기 → 문구 입력 → **추가** → 체크 → **문제에 반영**
  - 세트 그룹이면 "같은 그룹의 다른 세트에도 반영" 체크 가능 (단, '문제지 전체' 피드백만 다른 세트로 감)
- **직접 편집**: 3 문제 제작 → 결과의 문항 카드 → **편집**
- **검수 지적 고치기**: 4 검수 → 항목 체크 → **선택 n건 자동 수정**
- **되돌리기**: 3 문제 제작 → **버전 기록** → 되돌리기
- **다시 만들기**: 3 문제 제작 → **새로 제작** (이전 문제는 버전 기록에 남음)

### B. 출제 지침 (앞으로 계속 적용)
- **피드백으로**: 6 피드백 → 체크 → **지침·자료 설정 제안** → 제안 카드에서 고르고 반영 범위(이 프로젝트만 / 기본 지침) 선택 → 반영
  - 특정 양식·학년에만 해당하는 규칙(예: KSC 기호 규칙)은 반드시 **이 프로젝트만**. 기본 지침을 고르면 모든 프로젝트에 퍼진다(앱이 확인 창을 띄움).
- **직접 수정**: 왼쪽 메뉴 **출제 지침** → 기본 지침 또는 프로젝트 선택 → 편집·저장 (변경 기록 남음)
  - 프로젝트에서 기본 지침을 다르게 쓰려면 **이 프로젝트용으로 수정**
- **이 문제집만**: 3 문제 제작 → 적용할 지침 체크 / **이 문제집 전용 지침** 입력 → 설정 저장
  - 새 문제집은 지침이 하나도 체크되지 않은 상태로 시작한다. 검수도 여기서 체크한 지침만 쓴다.
  - 지침끼리 충돌하면 검수에 "지침 충돌" 지적이 나온다 → 어느 지침이 맞는지 정하고, 틀린 쪽을 해제하거나 고친다.
- 지침을 바꾼 뒤 **이미 만든 문제에는 자동 반영되지 않는다** → 문제에 반영 또는 새로 제작 필요

### C. 자료 (프로젝트 → 자료실 · 본문 탭)
- 자료 카드: **범위**(출제 범위/참고만/제외), **지문 사용 방식**(원문 그대로/패러프레이징/일부 변형 허용), 메모
- 패러프레이징이면: **분량**(원문과 비슷하게/짧게/길게/단어 수 지정), **난이도**(원문 수준/쉽게/어렵게/고1~고3 하·중·상/수능), **패러프레이징 메모**
- **본문 나누기 / 다시 나누기** (Codex), 본문 목록에서 이름·경계 편집, 숨기기(눈 아이콘), 직접 추가
- 문제지 샘플(공통) 업로드

### D. 제작 설정 (3 문제 제작)
- 일반 문제지: 제목, 객관식·서술형 수, 유형별 문항 수, 목표 난이도, 정답 번호 배분, 추가 요청
- 양식(지문 세트형): 제목, **지문 수**, **정답 번호 분포**(고르게 / 고르게 + 3·4·5번 조금 더), 추가 요청
- **본문 배정**: 자동 배정 / 자동으로 다시 배정 / 표에서 직접 수정 / 배정 해제
- 세트 그룹(프로젝트 → 문제집 탭): 모의고사 세트 만들기, 본문 자동 배정, 본문 사용표, 전체 세트 제작, 세트 추가

### E. 양식 구성 (2 샘플 분석 — 양식 모드)
- 하위 문항별 **사용 / 사용 안 함 / 택1 묶음 A·B**
- **화살표로 문항 순서** 변경 → 출력 순서·앱 문항 번호에 반영 (이미 만든 문제에도 바로 적용)
- 문항마다 **출제 메모** 편집 → 제작·검수 프롬프트에 그대로 들어간다 (지문 표시 기호, 문항 형식 등)
  - **다시 분석**하면 메모·사용 여부가 새로 만들어진다(출력 서식과 순서는 유지). 메모를 직접 고쳤다면 다시 분석 전에 알려 준다.
  - 메모(문항 형식)와 이미 만든 문항이 다르면 검수가 매번 지적한다 → 메모를 실제 원하는 형식으로 고치거나 문항을 다시 만든다.

### F. 출력 서식 (2 샘플 분석 — 양식 모드, '출력 서식' 카드)
- 블록 머리 출처 표기 **형광펜** 켜기/끄기
- **숨긴 정답 서식**: 형광펜 / 굵게 / 밑줄 / 흰 글씨 조합 (교사용에만 적용, 학생용은 빈칸)
- **하위 문항 사이 빈 줄** 수 (양식 그대로 / 0~3줄)
- **앞쪽 지문별 박스**(Logic Flow 등): 글자 크기(pt), 정렬, 각 줄 핵심어를 숨긴 정답 서식으로(학생용은 채우기 빈칸)
- **상자 안 내용 정렬**: 지문 상자, 삽입 문장 상자, <조 건>, <보 기> 등 (제목 줄 제외)
- 바꾼 뒤 → 5 HWPX 출력 → **양식 배치 후 HWPX 만들기**

### G. 일반 문제지 출력 (2 샘플 분석 → 출력 템플릿, 5 HWPX 출력)
- 출력 템플릿: 머리 영역 끝, 제목/발문/지문/선택지/정답/해설에 쓸 샘플 문단, 선택지 번호 방식
- 출력: 문제지 / 정답 및 해설 / 합본, 샘플 서식 사용, 머리 영역 유지

### H. 모델 (왼쪽 메뉴 모델 설정)
- 단계별 모델·effort, 묶음 크기, 동시 실행 수, 제한 시간, 개인 codex 설정 무시
- 실행 버튼 옆 모델 표시를 눌러 이번 실행만 바꿀 수도 있음

| 타입·API 호출 | `frontend/src/api.ts` |

### 꼭 알아야 할 규칙
- **정답 표시 마크업** (양식 배치 결과 `fills`):
  - `{{텍스트}}` 인쇄되는 내용 중 정답(선택지·기호) → 교사용 형광펜, 학생용 그대로
  - `{{?텍스트}}` 써 넣는 답 → 교사용 형광펜, 학생용 빈칸
  - `{{!텍스트}}` 숨긴 답 → 교사용 '숨긴 정답 서식', 학생용 빈칸
  - 일반 서식: `==형광펜==`, `**굵게**`, `__밑줄__`(밑줄 정확히 2개만, `__________` 빈칸은 글자 그대로), `!!흰 글씨!!`
- 제작 단계(내용)에서는 정답 표시를 하지 않는다 — `clean_item`/`clean_passage`가 지운다. 정답 표시는 배치 단계에서만.
- **배치 프롬프트나 배치 규칙을 바꾸면 `form_pipeline.LAYOUT_RULES_VERSION`을 올린다** (안 올리면 기존 배치가 재사용됨).
- 배치에 영향을 주는 출력 서식 값을 추가하면 `content_hash()`에도 넣는다. 배치와 무관한 서식(크기·정렬·빈 줄)은 `build_form`에서만 처리 → Codex 재호출 없이 다시 출력된다.
- f-string이 아닌 문자열에 `{{{{…}}}}`를 쓰지 말 것 (Codex가 중괄호 4개를 흉내 냄). `render_answers`가 3개 이상 중괄호를 정리하긴 한다.
- 정답 번호 변환은 `checks.answer_index()` 사용 — 파이썬은 `'❹'.isdigit()`이 참이지만 `int('❹')`는 실패한다.
- 모든 Codex 호출은 `Ctx.call`을 거친다 (한국어 응답 규칙 + 중국어 감지 재시도).
- 다시 분석해도 `form_style`과 하위 문항 순서는 유지된다 (`main._execute` analyze 분기).
- 화면: `Select`는 `w-full`이라 폭을 줄 때 감싸는 `div`에 너비를 준다. 좁은 칸에는 설명과 버튼을 세로로 쌓는다.

```
## 항목별 처리

| # | 피드백 | 처리 | 방법 |
```

## 6. 현재 상태 조회 (추측하지 말고 확인)

서버: http://127.0.0.1:8765 · DB: `data/symaker.db` (SQLite) · 파일: `data/workbooks/<id>/exports/`, `data/projects/<id>/files/`

```bash
# 프로젝트·문제집 목록
sqlite3 data/symaker.db "select p.id, p.name, w.id, w.name from projects p left join workbooks w on w.project_id=p.id"
# 문제집 전체 상태 (분석·설정·문항·지침·출력 파일)
curl -s http://127.0.0.1:8765/api/workbooks/<wid>
# 프로젝트 자료·본문
curl -s http://127.0.0.1:8765/api/projects/<pid>/materials
# 지침 (프로젝트에서 실제로 쓰이는 것)
curl -s "http://127.0.0.1:8765/api/guidelines?project_id=<pid>"
# 규칙 검사만 빠르게
curl -s -X POST http://127.0.0.1:8765/api/workbooks/<wid>/checks
```

문제집 JSON에서 볼 곳: `analysis.form_segments`(양식 구성·순서), `analysis.form_style`(출력 서식), `spec`(제작 설정), `guideline_ids`, `questions.sets[].layout.fills`(실제 배치 텍스트), `exports`(출력 파일).

## 7. 코드 수정 후 확인

1. 백엔드 수정 → 서버 재시작 (자동 새로고침 없음)
   ```bash
   pkill -f "uvicorn app.main:app"; cd backend && uv run uvicorn app.main:app --host 127.0.0.1 --port 8765
   ```
   (사용자는 `./start.sh`로 다시 켜면 됨)
2. 프론트 수정 → `cd frontend && npx tsc -b && npm run build` (서버가 `frontend/dist`를 그대로 보여 줌, 새로고침만 하면 됨)
3. 다시 출력: `POST /api/workbooks/<wid>/run/layout` (body `{"modes":["teacher","student"]}`) — 배치가 바뀌지 않았으면 Codex 없이 몇 초 만에 다시 만들어짐
4. 결과 확인 — 화면 미리보기가 아니라 **파일 안**을 본다
   - 텍스트: `uv run python -c "from app.hwpx_io import hwpx_plain_text; print(hwpx_plain_text('<파일>'))"`
   - 서식(정렬·크기·굵게·밑줄·색·형광펜): `hwpx_io.parse_header` + 문단의 `paraPrIDRef`, run의 `charPrIDRef` 확인
   - 학생용에 `{{`, 정답 텍스트가 남았는지 검사
   - 구조 검증: `uv run python -m hwpx.tools.package_validator <파일>`
5. 보고: 항목별로 무엇을 고쳤는지, 확인한 방법, **한컴오피스에서 직접 열어 보지는 못했다는 점**(직접 열어 확인하지 못했으면 그대로 말한다).
