# SYmaker — 영어 문제지 제작·관리 웹앱

연도·학기별 프로젝트 안에서 여러 문제집을 만들고, 각 문제집을 6단계로 제작합니다.

1. **자료 등록** — 샘플 문제지·참고자료(txt, pdf, hwp, hwpx). HWP는 자동으로 HWPX로 변환
2. **샘플 분석** — 문제 유형, 난이도, 서식(글머리표·문단 번호·한글 형광펜) 분석 + 출력 템플릿 문단 지정
3. **문제 제작** — 지침 라이브러리 + 문제집 전용 지침으로 Codex가 출제 (정답 번호 1~5 자동 균등 배치)
4. **검수** — 규칙 검사(문항 수, 선택지 5개, 정답 분포, 서식 표기) + Codex 검수, 선택 항목 자동 수정
5. **HWPX 출력** — 샘플 HWPX의 서식을 복제해 문제지/정답해설/합본 생성
6. **피드백** — 문제 수정에 반영하거나, 승인을 거쳐 출제 지침에 버전으로 반영

출제 지침은 **기본 지침**(모든 프로젝트) + **프로젝트 수정본/전용 지침**으로 관리합니다.

### 프로젝트 자료실 · 본문 · 모의고사 세트

- **자료실**: 출제 범위 자료(부교재·교과서 등)와 공통 샘플을 프로젝트에 한 번 올리면 모든 문제집·세트가 함께 씁니다.
  자료마다 **범위**(출제 범위 / 참고만 / 제외), **지문 사용 방식**(원문 그대로 / 패러프레이징 / 일부 변형 허용), 메모를 정합니다.
- **본문 나누기**: 자료마다 본문 구분 방식이 달라도 Codex가 본문의 시작·끝 문구를 찾고, 앱이 원본에서 그대로 잘라 옵니다(본문 변형 없음).
  해석·어휘 목록·기존 문제의 발문은 제외됩니다. 목록에서 이름·경계·적합 유형을 고치거나 숨길 수 있습니다.
- **모의고사 세트**: 세트 N개를 각각 문제집으로 만들고, '본문 × 유형'을 규칙으로 배정합니다.
  한 세트 안 본문 중복 없음 · 다른 세트에서는 다른 유형 · 모든 본문을 고르게 · 자료별 비율 유지 · 본문에 맞지 않는 유형 회피.
  나중에 세트를 추가해도 이전 사용 기록을 피해 배정합니다. 배정표는 세트 화면에서 직접 고칠 수 있습니다.
- 검수 규칙: '원문 그대로' 지문이 바뀌었는지, '패러프레이징' 지문이 원문과 너무 같은지, 다른 세트에서 같은 본문을 같은 유형으로 냈는지.

### 양식 채우기 모드 (지문 세트형 — KSC 등)

샘플이 '지문 1개 + 하위 문항 여러 개' 블록이 반복되는 빈 양식이면 자동으로 이 모드가 됩니다.
- 구조 인식: 모든 구역을 읽어 블록(`[1]`, `[2]` …), 지문 상자, 하위 문항(자동 번호 발문·선택지·유형별 칸), 앞쪽 지문별 박스(Logic Flow 등)를 찾습니다.
- 분석: 하위 문항마다 유형과 사용 여부(사용 / 사용 안 함 / 택1 묶음)를 지침에 맞춰 정합니다. 분석 화면에서 바꿀 수 있습니다.
- 제작: 지문마다 Codex 한 번 — 지침대로 변형한 지문(빈칸·❶~❺·ⓐ~ⓔ·㉠~㉤·[A / B]·(A)~(D) 표시 포함), Logic Flow, 하위 문항을 함께 만듭니다.
- 출력: 세트마다 '양식 배치'(어느 칸에 무엇을)를 정한 뒤 양식을 복제해 채웁니다. 양식의 글꼴·자동 번호·표·쪽 구성은 그대로입니다.
  교사용은 지침의 정답 표시 규칙(형광펜, 흰 글씨+굵게)을 적용하고, 학생용은 정답 표시를 지우고 써 넣는 답은 빈칸으로 둡니다.

### 문항이 많을 때 (예: 객관식 25 + 서술형 10)

- 문항 수가 묶음 크기(기본 5)보다 많으면 **출제 계획표**(번호·유형·지문·출제 포인트·정답 번호)를 먼저 만들고,
  계획표를 묶음으로 나눠 Codex 세션 여러 개(기본 동시 3개)로 **병렬 제작**합니다. 실패한 묶음만 한 번 더 시도합니다.
- 검수는 **묶음별 검수 + 문제지 전체 점검**을 병렬로 돌립니다.
- 수정은 **요청이 걸린 문항만** 보내고 고친 문항만 받아 끼워 넣습니다.
- 서술형은 모범답안·채점 기준·배점을 갖고, 문제지에는 `[서술형 n]`과 답란, 정답지에는 채점 기준이 출력됩니다.
- 묶음 크기·동시 실행 수는 모델 설정 화면에서 바꿉니다.

## 실행

```bash
./start.sh
```

브라우저에서 http://127.0.0.1:8765 이 열립니다. 필요: `uv`, Node.js, 로그인된 `codex` CLI.

개발 모드: `cd backend && uv run uvicorn app.main:app --port 8765 --reload` 와 `cd frontend && npm run dev` (http://localhost:5173).

## 구조

- `backend/app/main.py` — FastAPI API, 작업 실행
- `backend/app/codex.py` — `codex exec` 실행기(단계별 모델/effort, `--output-schema`로 JSON 고정)
- `backend/app/pipeline.py` — 단계별 프롬프트와 출력 스키마
- `backend/app/stages.py` — 출제 계획 → 묶음 병렬 제작, 묶음 검수, 부분 수정
- `backend/app/guidelines.py` — 기본/프로젝트별 지침
- `backend/app/materials.py` — 자료실, Codex 본문 나누기(원문 위치 찾기)
- `backend/app/allocation.py` — 세트별 본문 × 유형 배정 규칙
- `backend/app/project_api.py` — 자료실·본문·세트 그룹 API
- `backend/app/hwpx_form.py` — 양식(지문 세트형) 구조 인식과 칸 채우기
- `backend/app/form_pipeline.py` — 양식 모드 프롬프트·데이터 변환
- `backend/app/hwpx_io.py` — HWP→HWPX 변환, 텍스트·서식 분석
- `backend/app/hwpx_writer.py` — 샘플 템플릿 기반 HWPX 생성 (`==형광펜==` → `hp:markpenBegin/End`)
- `backend/app/checks.py` — 규칙 기반 검수
- `frontend/` — React + Vite + Tailwind UI
- `data/` — SQLite DB와 업로드/출력 파일
